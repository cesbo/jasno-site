# Agent guide

This app uses jasno (`@jasno/core`). **Your training data does not know jasno.** It is not React, Solid, Vue, Svelte or Angular.

Before you write or review code, read `node_modules/@jasno/core/AGENTS.md` in full. It is the guide for the jasno version this project installs. If the file is missing, run `npm install` first.

## Site

- Content is `docs/<NN-section>/<NN-page>.md`: the directory is the section, the numeric prefix orders and is stripped from the URL (`/docs/guide/getting-started`); the first `# heading` is the title, the first paragraph the meta description, the h2s the on-page table of contents. `npm run docs` (run by every script) turns each page into `public/docs/<key>.json` (its content: nodes rendered by `src/md.ts`, no innerHTML) and `public/docs/<key>.md` (the source, for agents), writes the page index `src/docs.ts` (the only part in the bundle), `public/llms.txt`, and `src/docs-samples/*.ts`: every ```ts block becomes a module that `jasno check` type-checks (a `<!-- ts: declare ... -->` comment right before a block adds what it relies on; ```ts fragment skips the check). Diagnostics pages are generated the same way from the `errors/` guides in `@jasno/core`.
- `npm run dist` also prerenders every route into `dist/<path>/index.html` (`scripts/prerender.mjs`, happy-dom); a docs page's HTML carries its JSON as a `<script type="application/json" id="doc">` block, which the route loader reads on a direct load (after a client-side navigation it fetches `/docs/<key>.json`); the client mounts over the prerendered page. Views are imported statically so that the client render lands in the same task as the entry (should not flash; by analysis, not measured).
- No syntax highlighting: highlighters emit HTML, which the CSP blocks. If ever, it is a build-time transform in `build-docs.mjs`.
- Layout: the docs route names the layout `src/layouts/docs.ts`, which holds the page list (`DocNav`), so the list keeps its scroll from page to page. `DocView` renders one page (the article, its table of contents, the phone menu) and is built again for every page. App holds the one `router.outlet()` in `<main>`.
- **A new jasno version.** Change `@jasno/core` in `package.json`, run every rung, and in the same commit update each page that describes an API, a rule or a recipe that changed. The diagnostics pages follow the installed guides by themselves. Check the agent skill `public/skills/jasno/SKILL.md` too. A new RECIPES entry in `jasno.d.ts` that people need gets a section in its API page or a page in `docs/30-patterns/`.
- **Style of `docs/**/*.md`: simple English, STE-lite.** One fact per sentence, 25 words at most. Put the rule first, the reason in the next sentence, then the example. Subject first, active voice, present tense. Keep IT terms, but use one term per concept: *live* / *snapshot*, *flush*, *computed*. Split at colons, semicolons and ", so". `npm run docs` warns about longer sentences. The page `docs/20-api/10-reactivity.md` is the model.
- **Content rules of `docs/**/*.md`.** Write for people; agents have `llms.txt` and `AGENTS.md`, so do not address "the agent" as a reader. Describe what jasno is now: no history (what changed, when, why, which version), no status banners. Do not put figures or stories of one project in a page; a page explains the framework. One topic per page: a topic that has its own page (testing setup, validation) gets a link or a line in `PLAN.md`, not a paragraph here. The first paragraph after the title is the meta description: one or two sentences. Do not edit the `ts` fences, their `<!-- ts: -->` preludes or the h2 names (the table of contents and e2e tests use them) without running `npm run check`.
